# Doc2Patient — Device Compatibility and Responsiveness Report

This document records the responsive and device-compatibility work carried out on the
Doc2Patient v1 web application, the verification performed, and the remaining known
gaps. The consultation-room layout was intentionally left unchanged in this pass.

## 1. Scope

Improved and verified:

- Global layout shell (`base.html`) and shared CSS
- Admin dashboard and admin reports tables
- Patient, doctor, profile, 2FA, and post-consultation forms
- Landing, FAQ, How It Works, Contact, Doctors, Health Library, and article pages
- Vitals tables for patients and doctors
- Mobile navigation behaviour and reduced-motion handling

Explicitly not changed:

- Consultation-room video layout and controls
- WebRTC signalling logic
- Notification delivery logic

## 2. Changes

### 2.1 Global foundation

`app/templates/base.html`

- Added `viewport-fit=cover` for notched devices.
- Added safe-area padding on `body`.
- Added horizontal content padding (`px-4 sm:px-6 lg:px-8`) to the main container
  so cards and tables no longer touch screen edges on phones.
- Enlarged the mobile menu button to a 44x44 px touch target and added `aria-hidden`
  to the decorative icon.
- Added Escape-key and tap-outside closing for the mobile menu.
- Footer links are now tap-friendly and wrap instead of overflowing.

`app/static/css/tailwind.input.css`

- Added `.table-wrap` for consistent horizontally scrollable tables.
- Added `.form-input` and `.card-surface` component helpers.
- Added visible `:focus-visible` outlines for navigation links, menu buttons, and FAQ
  controls.
- Added a small-screen rule keeping form controls at 16px to prevent iOS input zoom.
- Added `prefers-reduced-motion` handling that disables animation and transitions.

`app/__init__.py`

- The `trans` template filter now treats a missing locale as English instead of calling
  the external translation service. This prevents failed outbound requests for clients
  that send no `Accept-Language` header.

Background slider (kept on all devices, per project decision):

- Rotation now stops when the browser tab is hidden and resumes when visible.
- Rotation is disabled entirely for users who prefer reduced motion.

### 2.2 Tables

`app/templates/admin/dashboard.html`, `app/templates/admin/reports.html`

- Wrapped both tables in `.table-wrap` so they scroll horizontally on narrow screens.
- Reduced cell padding to `px-3 sm:px-6`.
- Empty-state rows updated to match.

`app/templates/my_vitals.html`, `app/templates/view_patient_vitals.html`

- Switched to `.table-wrap` and consistent responsive padding.
- Added responsive page headings.

### 2.3 Forms and dashboards

- `patient_dashboard.html`: search field and button now stack below the `sm` breakpoint;
  the YouTube recommendation container now uses `aspect-video` (the previous
  `aspect-w-16 aspect-h-9` classes were not generated by the current Tailwind build)
  and the iframe has a `title`.
- `doctor_dashboard.html`: Confirm/Decline action row now wraps.
- `profile.html`, `login.html`, `register.html`, `report_issue.html`,
  `post_consultation.html`, `enable_2fa.html`,
  `view_article.html`: responsive padding, wrapping layouts, and constrained media.
- `enable_2fa.html`: QR image is now size-constrained with intrinsic dimensions, and the
  code entry form stacks on phones.
- `post_consultation.html`: article checkbox rows use larger targets and wrap.
- `admin/view_report.html`: fixed an invalid `</habel>` closing tag.
- `my_reports.html`: report header wraps instead of overflowing.

### 2.4 Public pages

- `landing.html`: responsive hero and section headings, reduced vertical padding on small
  screens, lazy-loaded testimonial images with descriptive `alt` text, wrapping footer
  links, and the sections are now wrapped in a `<main>` landmark.
- `faq.html`: responsive heading, `aria-expanded` on questions, `aria-hidden` on answers,
  and focus-visible styling.
- `doctors.html`: lazy-loaded profile images with descriptive `alt` text and intrinsic
  dimensions.
- `health_library.html`: responsive heading and card title sizing with word breaking.
- `how_it_works.html`, `contact.html`: responsive headings and container padding.

The stylesheet cache version was bumped to `?v=2` so clients pick up the rebuilt CSS.

## 5. Consultation room mobile redesign (phases A–C)

The consultation room was redesigned for phones and tablets while leaving the desktop
layout unchanged. All changes are gated behind responsive classes so that `lg` and up
renders exactly as before.

### Phase A — Stage and self-view

- The other participant (remote video) fills the stage; your own video becomes a small
  thumbnail in the top-right corner with a "You" badge.
- Participant name and role move to the top of the stage on mobile. The per-tile labels
  remain at the bottom-left on desktop.
- The forced `100vh` height was removed on mobile; the stage is now capped with
  `aspect-video` and `max-h-[46dvh]` so it cannot swallow the screen.
- Desktop keeps the two equal tiles side by side inside the fixed-height column.

### Phase B — In-stage controls and call safety

- Microphone, camera, and end-call buttons now sit inside the stage on mobile, over a
  gradient scrim, with 48px touch targets and `env(safe-area-inset-bottom)` padding.
- Desktop keeps the original floating control pill.
- Mute and camera buttons expose `aria-pressed` and swap their `aria-label` between
  mute/unmute and camera on/off.
- End call now opens an inline confirmation sheet for both roles instead of ending the
  call immediately. The safe option ("Keep the call") receives focus when the sheet
  opens; Escape and backdrop clicks close it and return focus to the end-call button.
  Confirming stops the tracks, closes the peer connection, emits `hang_up`, and then
  redirects (doctor to the follow-up page, patient to their dashboard).

### Phase C — Vitals and chat

- Both panels remain visible together on mobile, matching desktop: the stage is followed
  by the Vitals card (all eight readings) and then the Live Chat card.
- No tabbed interface was added, per project decision.
- The chat card is capped at `max-h-[55dvh]` on mobile with its message list scrolling
  internally, so the message input stays reachable.
- The "Plan Follow-Up" button was removed from the consultation room because ending the
  call already routes the doctor to that page. "Send My Latest Vitals" remains in the
  Vitals card for patients only.

### What was deliberately preserved

The signalling contract is unchanged: `join`, `i_am_ready`, `peer_is_ready`,
`offer`/`answer`/`candidate`, `hang_up`, `message`, `fetch_latest_vitals`,
`vitals_update`, and the `peer_left` redirect. The ICE candidate queue, TURN
configuration, and `playsinline`/`muted` attributes are untouched.

### Verification performed

- Template render checks for the consultation page as patient and doctor: 200.
- 16 structural assertions on the rendered HTML (stage sizing, self-view thumbnail,
  in-stage scrim, safe-area padding, dialog markup, `aria-pressed`, both panels present,
  patient-only vitals button, no tab list, socket handlers intact, stylesheet `?v=3`).
- Inline JavaScript extracted from the rendered page and validated with `node --check`.
- Real-browser verification with Chrome via the DevTools Protocol using fake media
  devices:
  - Mobile 390x844: stage 342x192 with the remote tile filling it, self-view thumbnail
    96x54 in the top-right, both panel cards visible below.
  - Desktop 1280x800: two equal 419x584 tiles side by side with labels correctly placed
    inside each tile, and the floating control pill centred as before.
  - Control state: mute and camera toggles set `aria-pressed`, update their labels, and
    disable the corresponding media track.
  - End-call sheet opens with `End this consultation?` and focuses "Keep the call".

### Phase D — Connection status, call timer and keyboard handling

- A connection badge on the mobile stage header shows Connecting, Connected,
  Reconnecting, Connection failed, or Disconnected, driven by the peer connection
  `connectionstatechange` event and the Socket.IO connect/disconnect events.
- A call timer starts when the peer connection reaches `connected` and counts up in
  `mm:ss`, resetting on failure, close, or when the call is ended.
- The status text is exposed through `role="status"` and `aria-live="polite"` so screen
  readers are told when the connection changes.
- `window.visualViewport` is used to detect the on-screen keyboard. When the keyboard
  opens the stage gains a `keyboard-open` class and compacts to `26dvh` so the chat input
  and the newest messages stay reachable. Focusing the message input also scrolls it
  into view.

### End-to-end WebRTC test (two real browsers)

Two headless Chrome instances were driven through the DevTools Protocol, logged in as the
seeded patient and doctor, and both opened the same confirmed appointment. Chrome's fake
media device flags supplied a camera and microphone on each side.

Result, on both participants:

| Check | Patient | Doctor |
|---|---|---|
| Local media tracks | 2 (audio + video) | 2 (audio + video) |
| Remote media tracks received | 2 | 2 |
| Remote video dimensions | 640x480 | 640x480 |
| Connection badge | Connected | Connected |
| Call timer advancing | 00:04 then 00:08 | 00:04 then 00:08 |
| Role-specific UI | "Send My Latest Vitals" present | absent |
| Chat join broadcast | received | "System: ama has entered the room." |

This confirms the full path end to end: Socket.IO signalling (`join`, `i_am_ready`,
`peer_is_ready`, `offer`/`answer`/`candidate`), peer connection establishment, and
bidirectional audio/video delivery, plus the new connection badge and timer.

Limitations of this test: both peers were on the same host over `127.0.0.1`, so no NAT
traversal, TURN relay, or real network conditions were exercised. Those still require the
deployed environment.

### Still outstanding

- Optional follow-ups: camera flip (front/back) and a pre-call device check.
- NAT traversal across real networks (needs the deployed HTTPS instance and TURN).

## 6. Known remaining work

- **Consultation room** phases A–D are implemented and browser-verified, including a
  two-browser end-to-end call on the same host. Real-network NAT traversal still needs
  the deployed instance and TURN credentials.
- The mobile stage is sticky while the lower content scrolls. Vitals are collapsed by
  default below `lg` and can be expanded on any viewport; all eight readings remain
  available.
- Mute and camera controls now show their active state visually and through
  `aria-pressed`. The doctor appointment queue uses wrapping mobile actions, clear POST
  actions, and clearer pending status presentation.
- **WebRTC over the internet** is unverified: the local test used fake devices on the same
  host. A cross-network test on the deployed site is still required.
- **Notifications** (doctor appointment email/SMS and the patient confirmation message)
  have not been tested against live SMTP or Hubtel delivery.
- Patients now have a responsive consultation-history queue and detail view for completed
  doctor findings, care plans, recommended articles, and attached documents.
- **Background slider** still runs on all devices by project decision; it pauses when the
  tab is hidden and is disabled for reduced-motion users, but it continues to cost some
  mobile bandwidth and battery.
- Tables scroll horizontally on phones rather than switching to stacked cards.
- Manual screen-reader and real-device testing has not yet been performed.
